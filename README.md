# Pocket Notes

تطبيق ملاحظات كامل مبني على React + TypeScript + Vite، بتصميم الورق الأصفر وواجهة iPhone الكلاسيكية. يحتفظ ببنية المشروع المرفق وآلية تخزينه، مع هوية **Pocket Notes** والأيقونة التي قدّمها صاحب المشروع. يُستخدم [الموقع المرجعي](https://classic-pocket-notes.dyoth69.chatgpt.site) لمقارنة السلوك والميزات؛ تفاصيل التحقق والاختلافات المتبقية موجودة في [سجل التحقق الحالي](docs/VALIDATION.md).

## الوظائف الموجودة

- إنشاء الملاحظات وتحريرها وحفظ كل تعديل تلقائيًا في المتصفح.
- اشتقاق العنوان من أول سطر غير فارغ، مع دعم النص العربي والإنجليزي واتجاه الكتابة التلقائي.
- البحث الفوري في العنوان والمحتوى؛ لا تظهر الملاحظات المحذوفة في البحث الرئيسي.
- تثبيت الملاحظات وإلغاء تثبيتها، وترتيب كل مجموعة حسب آخر تعديل.
- سلة Recently Deleted لمدة 30 يومًا، مع المدة المتبقية والاستعادة والحذف النهائي بعد التأكيد.
- تنظيف المحذوفات المنتهية عند فتح التطبيق، حتى بعد إغلاقه لمدة تزيد على 30 يومًا.
- مشاركة الملاحظة عبر Web Share API، أو نسخها، أو تحديد النص للنسخ اليدوي عند تعذر الوصول إلى الحافظة.
- حفظ البيانات القديمة دون تغيير مفتاح التخزين، مع رسائل واضحة عند تعذر الحفظ أو تعارض تعديل من تبويب آخر.
- الورق الأصفر المسطر والخط المحلي والأزرار والانتقالات والتصميم المتجاوب.
- ملفات PWA وأيقونات التطبيق والعمل دون اتصال بعد اكتمال تحميل ملفات التطبيق أول مرة أثناء الاتصال.

## الرفع إلى GitHub والنشر

رفع الشيفرة إلى GitHub ونشر الموقع خطوتان منفصلتان. يُجري workflow الاختبارات والبناء عند الدفع إلى `main` أو فتح طلب سحب إليه. **نشر GitHub Pages معطّل افتراضيًا**؛ رفع المصدر وحده لا يفعّله.

### تجهيز مستودع المصدر

1. افتح مجلد `pocket-notes` الذي يحتوي `package.json`.
2. إذا لم يكن المشروع مرفوعًا بالفعل، أنشئ مستودعًا فارغًا باسم `pocket-notes` واجعل الفرع الرئيسي `main`. يمكنك اختيار مستودع خاص.
3. ارفع **محتويات المجلد** إلى جذر المستودع؛ يجب أن يظهر `package.json` مباشرة في الصفحة الرئيسية للمستودع. لا ترفع ZIP وحده، ولا تضع المشروع داخل مجلد إضافي.
4. تأكد من رفع `.github/workflows/pages.yml` و`.nvmrc` و`.gitignore` و`.gitattributes` أيضًا. في Finder على Mac يعرض الاختصار **Command + Shift + .** الملفات التي تبدأ بنقطة. يحافظ Git أو GitHub Desktop على البنية الكاملة.
5. راجع الملفات المرحلية قبل الدفع. لا ترفع `node_modules/` أو ملفات البيئة أو كلمات المرور أو مفاتيح الوصول. يتجاهل `.gitignore` ملفات البيئة وملفات الاعتماد الشائعة ونتائج البناء.

هذه التعليمات لا تعني أن مستودعًا قد أُنشئ أو أن الملفات رُفعت؛ حالة الرفع الفعلية والرابط، إن اكتمل الرفع، تُذكر في تقرير التسليم.

### الرفع من الطرفية

لمستودع جديد فقط، نفّذ الأوامر من داخل مجلد المشروع بعد إنشاء مستودع GitHub فارغ. استبدل `YOUR_USERNAME` باسم حسابك، واستخدم عنوان المستودع الفعلي:

```sh
git init -b main
git add .
git diff --cached --stat
git commit -m "Prepare Pocket Notes"
git remote add origin https://github.com/YOUR_USERNAME/pocket-notes.git
git push -u origin main
```

إذا كان المشروع يحتوي مستودع Git وremote بالفعل، استخدمهما بدل إعادة تنفيذ أوامر التهيئة وإضافة `origin`.

### تفعيل GitHub Pages اختياريًا

فعّل هذه الخطوات فقط عندما ترغب في نشر الموقع وتكون Pages متاحة لحسابك ومستودعك:

1. افتح **Settings → Pages → Build and deployment → Source** واختر **GitHub Actions**.
2. افتح **Settings → Secrets and variables → Actions → Variables**، وأنشئ **Repository variable** باسم `ENABLE_PAGES` وقيمة `true`. هذا متغير إعداد عادي، وليس سرًا.
3. افتح **Actions → Check Pocket Notes and optionally deploy Pages → Run workflow** واختر `main`.
4. بعد نجاح مهمة `deploy` سيظهر رابط التطبيق في صفحة التشغيل وفي **Settings → Pages**.

بعد التفعيل تُختبر التحديثات التالية على `main` وتُنشر تلقائيًا؛ طلبات السحب تُختبر دون نشر. لإيقاف النشر في التشغيلات اللاحقة، احذف `ENABLE_PAGES` أو غيّر قيمته إلى `false`. لا يؤدي ذلك إلى إزالة موقع نُشر سابقًا.

لا تحتاج إلى كتابة اسم المستودع داخل الكود؛ مسارات الملفات وملفات PWA نسبية، فتعمل تحت `/اسم-المستودع/` وكذلك على جذر نطاق مخصص. يجب أن تكون GitHub Actions وPages متاحتين ومفعّلتين وفق إعدادات الحساب والمستودع. إذا كان الفرع الرئيسي باسم آخر، عدّل `main` وشروط `refs/heads/main` في ملف workflow. راجع [دليل GitHub الرسمي](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) لإعداد Pages.

## التشغيل على جهازك

ثبّت Node.js **22.18 أو أحدث**؛ ملف `.nvmrc` يختار أحدث إصدار من Node 22 عند استخدام nvm. لا يلزم مفتاح API أو حساب أو قاعدة بيانات.

التقنيات الحالية: React **19.1.1**، TypeScript **5.9.2**، Vite **7.3.6**، وخط Patrick Hand محلي. لا توجد مكتبات تشغيل جديدة مضافة لأجل تغيير الهوية أو الأيقونات.

```sh
npm ci
npm run dev
```

افتح الرابط المحلي الذي يظهر في الطرفية. لفحص نسخة الإنتاج:

```sh
npm run check
npm run preview
```

| الأمر | النتيجة |
| --- | --- |
| `npm ci` | تثبيت الإصدارات المحددة في `package-lock.json` |
| `npm run dev` | خادم التطوير |
| `npm test` | اختبارات منطق الملاحظات والتخزين والمشاركة |
| `npm run build` | فحص TypeScript وبناء الواجهة وملف العمل دون اتصال داخل `dist/` |
| `npm run test:build` | فحص ناتج البناء والمسارات والأيقونات وService Worker؛ يُنفذ بعد البناء |
| `npm run check` | الاختبارات ثم البناء ثم اختبارات النشر |
| `npm run preview` | معاينة `dist/` عبر خادم محلي |

ينشئ البناء مجلد `dist/` الذي يمكن نشر محتوياته على استضافة ملفات ثابتة. لا يلزم تتبعه في Git؛ يعيد workflow بناءه من المصدر، ويتجاهله `.gitignore`. لا تفتح `index.html` بالنقر المزدوج عبر `file://`؛ شغّله عبر الخادم المحلي أو استضافة HTTPS. `vite preview` مخصص للمعاينة المحلية، كما يوضح [دليل Vite](https://vite.dev/guide/static-deploy.html).

## الهوية وأيقونة التطبيق

اسم التطبيق وعنوان الصفحة وmetadata وManifest هو **Pocket Notes**. الشعار البني والذهبي المقدم في `PocketNotes.png` محفوظ دون تغيير في `assets/branding/pocket-notes-original.png`، بمقاس **1254 × 1254** وصيغة PNG شفافة.

الأصول الجاهزة داخل المشروع:

| الأصل | الاستخدام |
| --- | --- |
| `public/icons/v2/favicon.ico` | أيقونة المتصفح بمقاسات 16 و32 و48 داخل ملف واحد |
| `public/icons/v2/favicon-16.png` و`favicon-32.png` و`favicon-48.png` | نسخ PNG لمقاسات favicon |
| `public/icons/v2/apple-touch-icon.png` | أيقونة شاشة رئيسية بمقاس 180 × 180 وخلفية معتمة |
| `public/icons/v2/icon-192.png` و`icon-512.png` | أيقونات PWA العامة بمقاسي 192 و512 |
| `public/icons/v2/icon-maskable-192.png` و`icon-maskable-512.png` | أيقونات maskable بخلفية معتمة ومساحة آمنة حول كامل الصورة |
| `public/manifest-v2.webmanifest` | تعريف الاسم ونطاق التشغيل والأيقونات والتشغيل المستقل |

تم اشتقاق الأيقونات بإعادة تحجيم الصورة الأصلية مع الحفاظ على نسبها وكامل محتواها. توضع الصورة في أيقونات maskable داخل دائرة الأمان المركزية، لحماية الرسم والاسم عند قص الأيقونة بواسطة النظام.

### إعادة توليد الأيقونات اختياريًا

الأيقونات الناتجة مضمّنة في المصدر؛ **لا تحتاج Python أو Pillow للتشغيل أو البناء أو CI**. لإعادة توليدها عند صيانة الأصول فقط، شغّل السكربت باستخدام Python تتوفر فيه مكتبة Pillow:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install Pillow
.venv/bin/python scripts/generate-icons.py
```

السكربت لا يعدّل الصورة الأصلية ولا يولّد تصميمًا جديدًا. احتفظ ببيئة Python المحلية خارج ملفات Git إذا استخدمت اسمًا مختلفًا عن `.venv`.

## الاختبارات

اجتاز `npm run check` **26 اختبارًا للمنطق والتخزين والمشاركة** و**10 اختبارات للبناء والنشر**، إضافة إلى فحص TypeScript وبناء الإنتاج. تتضمن اختبارات النشر مسارات جذر الموقع ومستودع `pocket-notes` والمسار القديم ومسارًا متداخلًا، واكتمال ملفات العمل دون اتصال، وسلامة مقاسات الأيقونات وصيغها.

نتيجة `npm audit` بعد تحديث Vite إلى `7.3.6` كانت **صفر ثغرات معروفة** وقت التحقق. قد تتغير قاعدة بيانات الثغرات لاحقًا؛ أعد الفحص عند تحديث الاعتماديات أو تجهيز إصدار جديد.

الاختبارات الآلية لا تثبت وحدها جميع تفاعلات المتصفح أو دعم أنظمة الهاتف. نتائج اختبار الواجهة والموقع المرجعي والقيود الفعلية موثقة في [سجل التحقق الحالي](docs/VALIDATION.md). الوثائق التاريخية المرفقة لا تُستخدم لإثبات اختبارات Pocket Notes الحالية.

## البيانات القديمة وتغيير الرابط

مفتاح التخزين بقي **`classic-pocket-notes:v1`**. صيغة البيانات هي `{ version: 2, notes: [...] }`، وتُقرأ صيغة الإصدار الأول أيضًا. حقول الملاحظة:

```ts
{
  id: string;
  content: string;
  createdAt: string;
  updatedAt: string;
  deletedAt: string | null;
  isPinned: boolean;
}
```

الملاحظات القديمة التي لا تحتوي الحقلين الجديدين تُقرأ بقيمتي `deletedAt: null` و`isPinned: false`، مع الاحتفاظ بالمحتوى والتواريخ والمعرّفات والحقول الإضافية. يتم التحقق من البيانات قبل استبدالها؛ البيانات غير الصالحة تبقى دون مسح مع إظهار رسالة للمستخدم. تغيير الاسم أو إعدادات GitHub لا يغير نموذج التخزين.

**الملاحظات الشخصية ليست جزءًا من ملفات المشروع.** يحتفظ المتصفح بها على أصل الموقع، أي البروتوكول والنطاق والمنفذ. عند فتح نطاق GitHub Pages جديد ستبدأ بمساحة تخزين منفصلة؛ الملاحظات الموجودة في الرابط القديم تبقى هناك، ولا تنتقل تلقائيًا أو تتزامن. لنقل نصوص ملاحظاتك: افتح كل ملاحظة في الموقع القديم، انسخها باستخدام المشاركة/النسخ، ثم أنشئ ملاحظة في الرابط الجديد والصقها. هذا ينقل النص، ولا ينقل تاريخ التعديل أو حالة التثبيت تلقائيًا.

التخزين مرتبط بأصل الموقع لا باسم المسار. نسختان من التطبيق على نفس أصل `https://username.github.io` تستخدمان مفتاح الملاحظات نفسه. أما ذاكرة ملفات العمل دون اتصال فهي منفصلة لكل مسار، بحيث لا يحذف تحديث إحدى النسخ ملفات نسخة أخرى. بقيت بادئة cache التقنية `classic-pocket-notes:` ليتعرف التحديث على الذاكرات القديمة ويحذف المتقادم منها في نطاقه فقط.

لا توجد مزامنة بين الأجهزة، ولا دمج تلقائي لتعديلات متزامنة في تبويبات مختلفة. عند ظهور تعارض يُطلب الاحتفاظ بالنص غير المحفوظ قبل إعادة التحميل. مسح بيانات الموقع يمسح الملاحظات؛ حذفها النهائي وانتهاء الاحتفاظ غير قابلين للتراجع. تعتمد مدة 30 يومًا على ساعة الجهاز، وتُحسب كـ `30 × 24` ساعة فعلية.

## التوافق والعمل دون اتصال

التصميم يحاكي iOS القديم، بينما يستهدف التطبيق متصفحات حديثة. واجهة المشاركة الأصلية والإضافة إلى الشاشة الرئيسية ولوحة المفاتيح تعتمد على دعم المتصفح والنظام. العمل دون اتصال يتطلب HTTPS أو localhost وتحميلًا متصلًا مكتملًا أولًا؛ تحديث Service Worker ينتظر إغلاق تبويبات النسخة السابقة. الخط والأيقونات محليان ولا يحتاجان خدمة خارجية أثناء الاستخدام.

أيقونة Pocket Notes مشتقة من الصورة المقدمة للمشروع. تراخيص React وReact DOM وScheduler والخط موجودة في `public/licenses/`. لا تحتاج هذه النسخة إلى Capacitor أو Xcode؛ هي مشروع ويب/PWA.
